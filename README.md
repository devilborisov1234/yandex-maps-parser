# Сбор организаций и контактов из Яндекс Карт — Борисов

Собирает организации города с Яндекс Карт: название, рубрики, адреса, телефоны,
сайты, соцсети, координаты. Затем отдельным проходом обходит сайты организаций
и достаёт **почту и мессенджеры** — в самих картах почты нет.

---

## Что важно понимать до запуска

**1. В Яндекс Картах нет email.** Вообще. Ни в карточке, ни в ответе API.
Поэтому почта собирается вторым этапом — с сайтов самих организаций.
Без этого этапа в CSV не будет почт.

**2. Обход медленный и это нормально.** Запросы идут с паузами 4–9 секунд
и перерывами. При текущих настройках полный обход Борисова — около
**1900 запросов, примерно 4 часа**. Ускорять не нужно: высокий темп означает
блокировку, а после блокировки простой всё равно потерян.

**3. Прогон можно прерывать.** `Ctrl+C` в любой момент — очередь, прогресс
и таймеры сохраняются. Продолжение: та же команда, сбор идёт с места остановки.

**4. Склеивание филиалов.** Одна организация с несколькими адресами — одна строка
в CSV, адреса и телефоны склеены.

## Порядок запуска

### Шаг 1. Проверить, что данные доступны

```powershell
.\.venv\Scripts\python.exe -m ymcontacts check
```

Команда делает ровно один запрос к картам (как в сборе), показывает, сколько
организаций пришло, и выводит три карточки: телефоны, сайт, соцсети,
координаты. Ничего не собирает и ничего не меняет — только проверка.

Если всё в порядке, двигаемся дальше.

### Шаг 2. Построить очередь обхода

```powershell
.\.venv\Scripts\python.exe -m ymcontacts plan
```

Покажет оценку: сколько запросов и сколько часов. Потом разложит задания:
общие запросы по мелкой сетке (2.2 км) и запросы по рубрикам по крупной (6.6 км).

Быстрый вариант (в 5–10 раз меньше запросов, покрытие ниже):

```powershell
.\.venv\Scripts\python.exe -m ymcontacts plan --rubrics none
```

### Шаг 3. Собрать данные из карт

```powershell
.\.venv\Scripts\python.exe -m ymcontacts sweep
```

Ограничить по времени (например, на 2 часа) и продолжить позже:

```powershell
.\.venv\Scripts\python.exe -m ymcontacts sweep --hours 2
```

### Шаг 4. Добрать почту с сайтов

```powershell
.\.venv\Scripts\python.exe -m ymcontacts sites
```

### Шаг 5. Выгрузить CSV

```powershell
.\.venv\Scripts\python.exe -m ymcontacts export
```

Результат: `data/out/борисов_contacts.csv`

## Все команды

| Команда | Что делает |
|---|---|
| `check` | Проверяет доступ к данным карт и показывает первые организации. Первый шаг |
| `plan` | Строит очередь обхода, показывает оценку объёма |
| `sweep` | Основной сбор из карт. `--hours N`, `--max-requests N` |
| `sites` | Обход сайтов за почтой и мессенджерами. `--limit N` |
| `export` | Склейка филиалов и выгрузка CSV. `--only-contacts` |
| `report` | Что собрано, что в очереди, заблокирован ли источник |
| `clear-cache` | Очистить кэш сырых ответов (после смены логики разбора) |

Если что-то не работает — начинайте с `check`: он делает тот же запрос, что и
сбор, и сразу показывает, есть ли данные.

### Как берутся данные

Запрос делается обычным HTTP-клиентом (`curl_cffi`, отпечаток Chrome), без
браузера. Адрес — это та самая страница, которую открывает человек:

```
https://yandex.by/maps/157/borisov/search/стоматология/?ll=28.485,54.2277&z=15&page=1
```

Организации лежат прямо в HTML, в блоке состояния
`<script type="application/json" class="state-view">`. Никакого запуска
JavaScript не нужно: страница отдаёт данные сразу.

Два параметра решают всё:

- `ll` — точка, вокруг которой ищет Яндекс (из неё делается сетка по городу);
- `page` — страница выдачи, на странице около 25 организаций.

Почему покрытие получается плотным

Поиск карт отдаёт около 25 организаций на страницу и ранжирует их **по
релевантности запросу**, а не по территории. Один запрос «стоматология» даст
популярные клиники всего города и пропустит половину мелких. Поэтому:

1. Город режется на сетку, в каждой ячейке делается общий запрос — так видно,
   какие рубрики в ней вообще есть.
2. По найденным рубрикам в ту же ячейку идут уточняющие запросы — так
   доходятся мелкие и редкие рубрики, вытесненные лимитом в 25 результатов.
3. Отдельно идут запросы по списку базовых рубрик.
4. Пустая страница выдачи закрывает хвост этой же выдачи: следующих страниц
   всё равно не будет, и запросы впустую не тратятся.

**Почему общий запрос — не название города.** Замер показал, что поиск по
«Борисов» не зависит от точки: из центра, юга, севера и запада приходит один и
тот же список из 17 организаций. Обход по сетке с таким запросом просто
повторяет один и тот же результат. Поэтому разведка идёт общими словами —
«организации», «компания», — которые в тех же точках дают 25/29/2/5 разных
организаций. Список запросов-разведчиков: `GENERIC_QUERIES` в
`src/ymcontacts/runner.py`.

Абсолютно полного обхода «всего» не гарантирует ни один такой источник.
Покрытие высокое, но не стопроцентное.

### Отказоустойчивость

| Что случилось | Что делает программа |
|---|---|
| Падение / Ctrl+C | Очередь и прогресс в базе, продолжение с места остановки |
| Таймаут, 5xx | Повтор с нарастающей паузой, максимум 3 попытки |
| Капча или 429 | Полная остановка источника на 45 мин. Таймер в базе, переживает перезапуск |
| Яндекс поменял схему ответа | Остановка с отчётом, данные сохраняются, нужен разбор в `yandex_ssr.py` |
| 404 | Задание проваливается, а не крутится вечно |
| Битый кэш | Кэш пропускается, идёт новый запрос |

Ошибки разделены на классы намеренно: на капчу «повторить с backoff» делает
ровно то, чего ждёт Яндекс.

### Кэш сырых ответов

Каждый ответ сразу пишется в `data/raw/*.json.gz`. Если завтра сломается
разбор, все уже скачанные данные на руках — разбор можно перепрогнать без сети.
Это же даёт возможность вручную посмотреть, что именно прислал Яндекс.

## Настройки (.env)

Все параметры — в файле `.env` (образец: `.env.example`). Код трогать не нужно.

### Темп

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `YMC_DELAY_MIN` / `MAX` | 4.0 / 9.0 | Пауза между запросами, случайно в этом диапазоне |
| `YMC_BREAK_EVERY` | 30 | После каждых N запросов — длинный перерыв |
| `YMC_BREAK_MIN` / `MAX` | 45 / 120 | Длительность перерыва, секунды |
| `YMC_MAX_REQUESTS_PER_HOUR` | 420 | Часовой потолок |
| `YMC_COOLDOWN_ON_CAPTCHA_MIN` | 45 | Остывание после капчи |

**Меньше — не значит быстрее в итоге.** Частая блокировка отнимает больше
времени, чем экономит агрессивный темп.

### Город

| Параметр | По умолчанию |
|---|---|
| `YMC_CITY_NAME` | Борисов |
| `YMC_CITY_CENTER_LAT` / `LON` | 54.2277 / 28.4850 |
| `YMC_CITY_RADIUS_KM` | 7.0 |
| `YMC_CELL_SIZE_KM` | 2.2 (общие запросы) |
| `YMC_RUBRIC_CELL_SIZE_KM` | 6.6 (запросы по рубрикам) |
| `YMC_MAPS_HOST` | https://yandex.by |
| `YMC_MAPS_CITY_SEGMENT` | borisov (обязателен, иначе 404) |

Другой город: поменять координаты центра и радиус. Удобный способ узнать
координаты — открыть карту, нажать правой кнопкой по центру города и выбрать
«Скопировать координаты».

### Этап 2: сайты

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `YMC_SITE_WORKERS` | 3 | Сколько сайтов одновременно. Больше 4 — заметная нагрузка |
| `YMC_SITE_DELAY_MIN` / `MAX` | 2.0 / 5.0 | Пауза между страницами одного домена |
| `YMC_MAX_PAGES_PER_SITE` | 3 | Главная + страницы контактов |

## Если что-то пошло не так

**Первым делом — `check`.** Он делает тот же запрос, что и сбор, и сразу
показывает, есть ли данные, телефоны и сайты.

**`check` отвечает `NotFoundError: HTTP 404`.**
В адресе не хватает сегмента города (`/maps/157/<город>/search/...`) — без него
Яндекс отвечает 404. Укажите `YMC_MAPS_CITY_SEGMENT` в `.env` латиницей
(например, `borisov`). Пустое значение означает «взять транслитерацию
`YMC_CITY_NAME`».

**`check` отвечает `CaptchaError` или `403`.**
Яндекс требует браузерный отпечаток — он уже включён в клиент. Значит, сработал
потолок запросов с вашего адреса. Подождите 30–60 минут и повторите; темп в
`.env` лучше уменьшить.

**Остановился сбор, в логе «структура ответа изменилась».**
Яндекс поменял формат ответа. Данные сохранены. Смотрите
`sources/yandex_ssr.py`: разбор сделан терпимым к разным версиям схемы, но
если блок состояния переехал — правьте `extract_state`.

**Постоянно появляется капча.**
Не хватает времени на остывание: запускайте с `--hours 1`, делайте перерывы
между запусками по 30–60 минут. Проверить состояние: `report`.

**Мало организаций в итоге.**
Проверьте `report`: сколько заданий осталось в очереди. Если очередь не пуста —
сбор просто не закончен. Докрутить: уменьшить `YMC_CELL_SIZE_KM`.

**Почт мало.**
Нормально: почта есть не у всех, а у части сайтов она в футере или на странице
«Контакты», которую обход иногда не находит. Увеличьте `YMC_MAX_PAGES_PER_SITE`
до 5.

**Нужен другой город.**
Меняется только `.env` и очередь. Старую очередь сбросить:
`python -c "from ymcontacts.storage import open_db; db=open_db(); db.conn.execute('DELETE FROM tasks'); db.conn.commit()"`.

## Юридическая сторона

Официальный API Поиска по организациям Яндекса для этой задачи не подходит:
его лицензия запрещает сохранять полученные данные и требует показывать их
на карте Яндекса. Поэтому здесь используется публичная выдача сайта карт.
Используйте собранные данные в рамках применимого законодательства, с учётом
требований о персональных данных и о правилах рассылок.
